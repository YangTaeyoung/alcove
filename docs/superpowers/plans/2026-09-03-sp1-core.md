# SP1 — Core app implementation plan

Goal: from the Alcove app, create a VM, boot it, see it, type and click in
it, pause/resume, shut down, snapshot, attach USB. Windows 11 ARM and Ubuntu.
Everything is tested without a GUI where possible.

Inputs: `docs/superpowers/specs/2026-09-03-alcove-design.md`,
`docs/display-protocol.md`, `docs/research/qemu-11.1.1-*.md` (verified notes
on QEMU internals — every QEMU API used must be cited from there or from the
source tree in `build/qemu-src`).

## Work packages

### WP1 — QEMU `alcove` display backend (C, in `qemu-patches/`)

Deliverable: `qemu-patches/0001-ui-add-alcove-display-backend.patch`, applied
by `scripts/build-qemu.sh` on top of v11.1.1. Pure C (`ui/alcove.c`), no
Objective-C, no threads.

- New qapi `DisplayType` member `alcove` and `DisplayAlcove` options struct:
  `socket` (str, required), `shmdir` (str, optional; defaults to the socket's
  directory). Meson feature option `alcove` (auto), `CONFIG_ALCOVE`.
- Registers a `QemuDisplay` with `init` that connects to the unix socket,
  registers one `DisplayChangeListener` per graphic console (`con` index),
  and installs the socket fd on the main loop (`qemu_set_fd_handler`).
- Owns a shadow framebuffer per console in a shared file
  (`<shmdir>/fb<con>-<generation>.bgra`, `mmap(MAP_SHARED)`), always
  `PIXMAN_x8r8g8b8`; `dpy_gfx_switch` (re)allocates when the size grows or
  format differs; `dpy_gfx_update` blits the dirty rect from the console
  surface into the shadow with pixman and emits `update`. Never blocks the
  main loop: outbound writes are non-blocking with a bounded queue; when the
  queue is full, drop `update` messages and set a `needs_full_refresh` flag
  that is flushed as a whole-surface `update` when the socket drains.
- Cursor via `dpy_cursor_define` (`cursor` message with its own shared file),
  `dpy_mouse_set` → `mouse`.
- Input: parses `key`/`abs`/`rel`/`btn`/`sync`/`ui`/`refresh` per the
  protocol document, calls the `qemu_input_*` API; `abs` in 0..32767 maps to
  `INPUT_EVENT_ABS_MIN..MAX`.
- Sends `hello` on connect and `bye` on exit (`atexit` or display cleanup).
- Test: `scripts/test/display-backend.py` (Python 3, stdlib only) boots
  `qemu-system-aarch64 -M virt -accel hvf -display alcove,...` with only the
  EDK2 firmware (no OS), waits for `switch` + `update`, maps the file, asserts
  the frame is not uniform (the TianoCore logo/boot menu is drawn), sends
  `key` Esc (enters the firmware setup UI), asserts new `update` messages
  arrive and pixels changed, then `abs`+`btn`+`sync` without error, and
  terminates QEMU cleanly. Exit 0 on success. Also `scripts/test/all.sh`.

### WP2 — `AlcoveDisplayProtocol` (Swift package target)

- `DisplayMessage` enum with `Codable` payload structs mirroring the
  protocol document exactly (both directions), a `LineCodec` for
  newline-delimited JSON (tolerant to unknown `t`), `SharedFramebuffer`
  (maps a file read-only with `mmap`, validates `size >= stride*h`, exposes
  `UnsafeRawBufferPointer`, unmaps on deinit).
- `DisplayConnection`: listens on a unix socket path (created by the app,
  mode 0600), accepts exactly one QEMU connection, exposes
  `AsyncStream<DisplayMessage.FromQEMU>` and `func send(_ msg: ToQEMU)`.
  Implemented with POSIX sockets + `DispatchIO`/`DispatchSource` (no
  Network.framework dependency), fully `Sendable`.
- `QKeyCode` (generated). `MacKeyMap`: `kVK_*` virtual keycode → `QKeyCode`
  for the full ANSI/ISO/JIS layout plus function/keypad/media keys. Table is
  written from Apple's `Events.h` constants and QEMU's qapi names, not copied
  from `ui/cocoa.m`.
- Tests: codec round-trips for every message, unknown-type tolerance,
  `SharedFramebuffer` on a temp file, `DisplayConnection` against an
  in-process fake "QEMU" client, `MacKeyMap` spot checks (`kVK_ANSI_A` →
  `.a`, `kVK_Command` → `.metaL`, `kVK_RightCommand` → `.metaR`).

### WP3 — `AlcoveQMP` (Swift package target)

- `QMPClient` actor: `connect(path:)` waits for the greeting, sends
  `qmp_capabilities`; `execute(_ command: String, arguments: [String: JSON]?) async throws -> JSON`
  correlates by `id`; `events: AsyncStream<QMPEvent>`; `JSON` enum value type;
  `QMPError` carrying class/desc; reconnect not required in v1.
- Typed helpers in `QMPCommands.swift`: `queryStatus`, `stop`, `cont`,
  `systemPowerdown`, `systemReset`, `quit`, `snapshotSave/Load/Delete`
  (job-based; waits for `JOB_STATUS_CHANGE` concluded and dismisses; surfaces
  job error), `queryNamedBlockNodes`, `blockdevChangeMedium`, `eject`,
  `deviceAdd(usbHost:)`, `deviceDel`, `screendump`, `migrate(uri:)` +
  `queryMigrate` polling, `inputSendEvent` (kept as an alternative input path).
  Argument names must match the research notes.
- Tests: fake QMP server over a unix socket (greeting, capabilities, echo of
  ids, event injection, error responses), timeouts, out-of-order responses.

### WP4 — `AlcoveEngine` (Swift package target)

- `VMConfig` (Codable, `schemaVersion`): name, guestOS (`.windows`, `.linux`,
  `.other`), cpuCount, memoryMiB, disks (path, size, bus `.virtioBlk|.nvme`),
  cdroms (ISO paths), network (`.user` with port forwards), display
  (`.virtioGPU|.ramfb`), input (`.usbTablet`), tpm (bool), efiVars, usb
  passthrough list (vendor/product), shared folders (reserved for SP2).
- `VMBundle`: `<dir>/<name>.alcovevm/` layout from the spec; create with
  `qemu-img create -f qcow2`, load/save `config.json`, `run/` scratch dir for
  sockets and shared files (cleared on start), `efi-vars.fd` copied from
  the engine's `edk2-aarch64-vars.fd` (or zero-filled 64 MiB if absent).
- `EngineLocator`: finds `qemu-system-aarch64`, `qemu-img`, firmware, and
  `swtpm`, in this order: app bundle `Contents/Resources/qemu/`, then
  `build/qemu-build` relative to the repo (dev), then `$PATH`.
- `QEMUCommandBuilder`: `VMConfig` + bundle → `[String]` argv. Golden tests
  for Linux and Windows profiles. Uses `-M virt`, `-accel hvf`, `-cpu host`,
  pflash pair, `-display alcove,socket=...,shmdir=...`, `-qmp unix:...,server=on,wait=off`,
  `-serial file:run/serial.log`, `-monitor none`, `-nodefaults`, `qemu-xhci`
  + `usb-kbd` + `usb-tablet`, `virtio-rng-pci`, `virtio-serial-pci`,
  network `-netdev user,id=net0[,hostfwd=...] -device virtio-net-pci`,
  disks per bus, cdroms as `usb-storage` on the xHCI controller (or the bus
  the research notes recommend for EDK2 boot), TPM when enabled
  (`-tpmdev emulator,id=tpm0,chardev=chrtpm -chardev socket,id=chrtpm,path=run/swtpm.sock -device tpm-tis-device,tpmdev=tpm0`),
  `-boot order` / `once`.
- `SwtpmProcess` and `QEMUProcess`: spawn via `Foundation.Process` with
  stdout/stderr captured into `run/*.log`, termination continuation, kill.
- `VMController` actor: states `stopped, starting, running, paused,
  suspending, stopping, failed(Error)`; observable via `AsyncStream<VMState>`;
  `start()`, `pause()`, `resume()`, `shutdown(force:)`, `reset()`,
  `snapshots()`, `createSnapshot(name:)`, `restoreSnapshot(name:)`,
  `deleteSnapshot(name:)`, `suspendToDisk()` / resume via `-incoming` on next
  start, `attachUSB(vendor:product:)`, `detachUSB(id:)`, `changeMedium(...)`.
  Owns `DisplayConnection` and `QMPClient` and exposes the display stream.
- `VMLibrary`: VM directory (`~/Library/Application Support/Alcove/VMs` by
  default, overridable), list/create/delete/rename bundles, watches for changes.
- `USBDeviceList`: IOKit enumeration of USB devices (vendor, product, names)
  for the passthrough menu.
- Tests: config round-trip and migration, bundle create/load, command builder
  golden output, controller state machine against a `FakeEngine` (fake QMP
  server + a stub display client), locator.

### WP5 — Alcove app (AppKit + SwiftUI)

- Library window: list of VMs with status, "New VM" wizard (name, guest OS,
  ISO picker, disk size, CPU/RAM sliders with sane defaults per OS), context
  menu (start, settings, snapshots, show in Finder, delete).
- VM window: `DisplayView` (`MTKView` subclass, first responder; NSEvent →
  protocol messages; HiDPI aware; aspect-fit with letterboxing; cursor
  overlay; capture Cmd-key combos only when focused; Ctrl+Cmd release),
  toolbar (Start/Pause/Resume, Shut down, Reset, Snapshots, USB, Settings),
  status bar (state, CPU/RAM), resolution follow-window option (sends `ui`).
- `MetalRenderer`: one `bgra8Unorm` texture per surface, updated with
  `replace(region:)` from the shared framebuffer for each dirty rect,
  drawn as a textured quad; redraw only when dirty, capped at display refresh.
- Settings sheet: CPU, RAM, disks (add/remove ISO), network port forwards,
  display device, TPM, boot order. Snapshots sheet: list, create, restore,
  delete with confirmation. USB menu: live device list, attach/detach.
- Error handling: engine missing, QEMU exit with log tail, socket loss.
- Menus and shortcuts, Dock badge for running VMs, quit confirmation while
  VMs run (offers suspend).

### WP6 — Integration and verification

- `scripts/test/all.sh`: builds engine, runs WP1 test, `swift test`,
  `xcodebuild build`.
- Manual run: launch app, create Ubuntu VM from the cloud image, boot to
  desktop-less login on the framebuffer (serial not needed), type a
  command, pause/resume, snapshot/restore, shut down. Screenshot for the
  report.

## Ordering and parallelism

WP1, WP2, WP3 are independent. WP4 depends on WP2+WP3 interfaces (fixed in
this plan). WP5 depends on WP2–WP4. WP6 last. Agents work in the same tree on
disjoint directories; `Package.swift` and `project.yml` are edited only by the
integrator.

## Definition of done (SP1)

1. `scripts/test/all.sh` passes on a clean checkout.
2. Ubuntu and Windows (installed via SP0's unattended script) both run in
   the app with keyboard and mouse.
3. Pause/resume, snapshot/restore, USB attach of a real device, shutdown,
   suspend-to-disk and resume all work from the UI.
4. Code review pass with no open correctness findings.
