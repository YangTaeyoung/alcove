## Checks adapted to the guest

- **Check 8.** The agent runs elevated, so what it starts is elevated and no
  UAC prompt appears. The check reads the tree and the text of a Notepad the
  agent started, asserts that the agent and that Notepad run at high
  integrity (0x3000), and reports whether a window of a higher level exists
  (none did: the levels on the desktop were 0x2000 and 0x3000).
- **Check 7.** Edge is started with `--user-data-dir=C:\alcove-e2e\edge-profile
  --no-first-run --new-window`. The pid `vm.app.launch` returns is a launcher
  that exits at once; the window belongs to its child, which the script ends
  with its process tree after checking that its command line names the
  profile folder. The window's title is `Untitled - …` at first, so the
  script waits for the page's title.
- **Check 12.** The agent is restarted in the guest (`schtasks /End` and
  `/Run` of `AlcoveAgent` from a process started through WMI, which outlives
  the task), so that the server makes a new connection. The check then makes
  no window or element request until `window.opened` of a `vm.app.launch`
  with `waitWindow: 0` has arrived.
- **Check 14.** A search without a match in File Explorer takes 0.14 s, too
  short to be in the way. The check uses the Services console instead (7 s to
  8 s) and skips itself with a note when that search takes less than 4.5 s.
- **Focus.** `vm.window.action focus` can be refused by Windows. The script
  then clicks the window's title bar and fails with the name of the window in
  front when that does not help. This happened while the OneDrive `Turn On
  Windows Backup` toast had the foreground after a reboot; the toast was moved
  to the notification centre by hand (`vm.ui.action invoke` on its `Move this
  notification to Notification Center` button) before the runs listed above.

## Changes to the older scripts

`at1-e2e.py` and `at3-e2e.py` failed on the integrated tree for reasons in
the scripts:

- both expected MCP texts without the `eventSeq <n>` line that changing tools
  now print, and `at3-e2e.py` the `observe must be one of …` sentence without
  `ui`;
- `at3-e2e.py` left the pointer on the line it reads next (the I-beam over
  `Alcove OCR check` made the recognizer miss the line: three of three runs of
  checks 5 and 6 alone); it now moves the pointer to the corner of the frame
  when it starts Notepad and after the click of check 4;
- `at3-e2e.py` expected the first click and the first typing in a new Notepad
  to settle within 2 s. In this guest Notepad keeps repainting for up to 8 s
  after its start (a change in the window 4.8 s and one in the taskbar 8.0 s
  after the start were sampled): the first typing was unsettled in two of
  four runs and the first click in one of seven. Check 3 now waits for a
  screen that stands still for 2 s and gives both observations 8 s to settle.

## What is not verified

- A window of a higher integrity level than the agent's, and the secure
  desktop of a UAC prompt.
- Electron and WebView2 apps; Chromium was run as Edge only.
- Display scale other than 100 %, several monitors, a locked session.
- `vm.deploy` with `install` (no installer was run in the guest), with a
  single file as `path`, and on a guest that is not Windows; these are
  covered by unit tests only.
- `vm.stop` / `vm.start` and `vm.snapshot.restore` moving the event baseline
  (unit tests only).
- A helper that the agent replaces after a request ran out of time, and the
  agent's `the UI helper is busy with '<op>'; retry` after 60 s in its queue.
- More than 500 kept events (`first` above 1) and `events.dropped`.
- `marksTruncated` (the fixture has 17 marks).
- The release build's timings.

## Seen in passing

  `build/DerivedData`) was started by something else at 10:26 local time and
  started the same VM: each host stops the engine it finds for a VM before it
  starts its own, so the guest was powered off uncleanly twice (Kernel-Power
  41 at 01:26:18 and 01:27:48 UTC) and the checks were repeated afterwards.
  The stale frames of the second defect above were found through this.
- `vm.window.list` does not list the notification toast while it has the

  selected a word instead of placing the caret.
- A helper that was ended by hand is started again by the next window or
  element request only; until then no window events arrive.
