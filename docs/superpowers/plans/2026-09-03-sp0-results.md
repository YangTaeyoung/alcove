Xcode 26.6) and is reproducible with the scripts named.

## Facts that changed the design

- **Unix socket paths are limited to 104 bytes on macOS.** VM sockets now live in
  `/tmp/alcove-<uid>/<12-hex hash of bundle path>/`; shared framebuffer files
  stay in the bundle's `run/` directory (referenced by absolute path in JSON).
- **`tpm-tis-device` fails under HVF on this host** (`HV_BAD_ARGUMENT` from
  `hv_vm_map`, accel/hvf/hvf-all.c:123). TPM is off by default; Windows 11
  installs with the LabConfig bypass keys and runs without a TPM.
- **No vsock on macOS hosts** (vhost is Linux-only), so guest tools will use TCP
  over the user-mode network (`10.0.2.2` from the guest); the Windows guest
  already reaches the host that way.
- **Keyboard mapping lives in QEMU.** `qemu_input_map_osx_to_linux` maps macOS
  virtual keycodes; the app sends `NSEvent.keyCode` as `mac` and keeps no table.
- **The first guest-programmed surface arrives as a second `switch`.** QEMU's
  initial placeholder ("Guest has not initialized the display (yet)") is a real
  surface; the backend copies whole surfaces on every switch and then relies on
  the device's own dirty rectangles (console.c emits no update after a real switch).
- **ramfb re-sends full-screen updates every refresh** (no dirty tracking), so
  idle detection must look at pixels, not message counts.
- **"Press any key to boot from CD" appears on the first Windows boot** and the
  Windows Setup GUI reacts to Space (it hit Cancel once); the harness taps Space
  only during the first 25 s.
- **`snapshot-save` needs block node names**, so the command builder uses
  `-blockdev` with `node-name=disk0` rather than `-drive id=`.
- **Incoming migration restores the saved run state (paused)**; resuming from
  suspend must issue `cont` after `query-status` reports not running.
