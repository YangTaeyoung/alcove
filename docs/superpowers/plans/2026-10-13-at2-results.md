## The two measured answers

**Agent connection and guest clock after `snapshot-load`.** Two raw
connections to the agent, one opened before the snapshot was taken and one
after, stayed open on the host after the load and never answered again: a
`ping` sent on each got no `pong` within 12 s, and neither was closed. A new
connection received `hello` at once, through the configured forward and
through two runtime forwards (one added before the snapshot, one after).
The guest clock continued from the snapshot's time: Windows logged a change of
+17 s to +53 s when `vm.snapshot.restore` set it, equal to the age of the
snapshot, and the guest was within 1.1 s of the host afterwards.

**DPI scale without signing out.** `SPI_SETLOGICALDPIOVERRIDE` (what
`dpiScale` runs) applies at once on this guest. After `dpiScale: 125` the
taskbar was redrawn 60 pixels high instead of 48, a DPI-aware process started
afterwards read a system DPI of 120, and `GetDpiForWindow` of a Notepad and a
Character Map window that were open before reported 120; `dpiScale: 100`
returned all three to 96. `HKCU\Control Panel\Desktop\WindowMetrics\AppliedDPI`
stayed at 96 throughout: it is the value of the last sign-in.

## Checks corrected for how Windows behaves

- **Firewall.** The first PowerShell process that listens on a port makes
  Windows Firewall add two Block rules named `Windows PowerShell` for
  `powershell.exe` on the Public profile. They outrank an Allow rule for the
  port, and a forwarded connection then opens on the host and delivers
  nothing. Check 3 adds its Allow rule for port 18080 before the listener
  starts (no Block rules appear then), removes it at the end and stops with
  the removal command when such Block rules already exist.
- **Network link.** `vm.status` keeps `tools: true` while the link is down, so
  it cannot tell when the guest tools are back. Check 4 retries its first
  guest-tools call after `up: true`.
- **Clock events.** `Set-Date` makes Windows log two clock changes, the jump
  and a correction of about a millisecond. Check 2 takes the largest change of
  the last 15 s.

## What differed from the plan

- The plan's Step 2 rebuilds `alcovectl` only. This run also rebuilt the
  engine, because the snapshot check needs `qemu-patches/0002`.
- `dpiScale` takes effect `now`, not at sign-out, and check 6 changes the scale
  to 125 % and back instead of only reading `takesEffect`.
- Check 2 also covers the refusals of `vm.snapshot.create`, a runtime forward
  across the restores and `alcove_snapshot_restore`; check 3 the agent row, the
  refusals for config and agent ports and a port in use on the host; check 5

  error result of `alcove_set_environment`.

- `README.md` states 53 tools and the 23 tools of `core`; the count had not

- `docs/control-protocol.md` gained the sections VM rows, Starting, Linked

## Open

- `snapshot-save` aborted the engine in about one of eight attempts on a
  firmware-only VM when it was taken within about a second of the start:
  `Error: ret = HV_ERROR (0xfae94001, at ../qemu-src/accel/hvf/hvf-all.c:77)`,
  the `hv_vm_protect` call that starts dirty tracking. It did not occur in the
  eight snapshots taken of the running Windows guest. Not investigated.
- A qcow2 image does not shrink when a snapshot is deleted; the VM's bundle is
  3.7 GiB larger than before its first snapshot.
- `dpiScale` passes the index of the percentage to
  `SPI_SETLOGICALDPIOVERRIDE`, which counts from the guest's recommended
  scaling. The two agree on this guest, whose recommended scaling is 100 %; a
  guest with another recommended scaling was not tried.
- `vm.status` reports `tools: true` while the network link is down, and the
  first guest-tools op after `up: true` can answer `disconnected during <op>`.
  Documented.
- `timeZone` takes the guest's own zone ids; an IANA name is not translated for
  Windows.
- `vm.status` showed `640x480` for a VM that had been restarted until a frame
  was read again; `width` and `height` are those of the latest frame read
  through the server.
- Two processes that own one VM directory, a clone created by another process
  between a template's epoch bump and its engine start, and a template bundle
  moved on disk are limits stated in `docs/control-protocol.md`.
- Not exercised: Linux guests (the `sh` recipes of `vm.set_environment` and
  `vm.doctor`), the Alcove app as the owner of the control socket, a VM with a
  suspended session, a VM with more than one disk, `vm.snapshot.restore` with
  guest tools that cannot run commands (`clockSynced: false`), a paused VM.
- The engine build that ran before this work is kept at
  `build/qemu-build-before-nvme-fix` (815 MiB, not tracked); it can be removed.
